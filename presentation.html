Fixed-Size: Simple and Fast

Document (5000 tokens) ↓ [500 tokens] [500 tokens] [500 tokens] ...

✅ Pros

  • Easiest to implement
  • Predictable chunk sizes
  • Fastest processing
  • Low cost

❌ Cons

  • Ignores structure
  • May split mid-sentence
  • Lower accuracy
Best For: Prototyping, simple content, high-volume processing
13 / 30

Recursive: The Reliable Default

1. Try splitting by paragraphs (\n\n) ↓ If too large 2. Try splitting by sentences (.) ↓ If too large 3. Try splitting by words ( ) ↓ Chunks that respect natural boundaries

✅ Pros

  • Structure-aware
  • Industry standard
  • Good balance of quality & simplicity
  • Works for 80% of use cases
⭐ START HERE: Recursive chunking is recommended as your baseline
14 / 30

Semantic: Topic-Based Intelligence

Sentence 1 → Embedding Sentence 2 → Embedding → Calculate Similarity Sentence 3 → Embedding → Calculate Similarity When similarity drops → New chunk boundary

✅ Pros

  • Topic coherence
  • Best retrieval (2-9% better)
  • Context preservation

⚠️ Cons

  • Computationally expensive
  • Higher API costs
  • Slower processing
Best For: High-accuracy requirements, research papers, complex documents

Chunking Best Practices

  1. Start with Recursive (512 tokens, 20% overlap)
    • Establish baseline, optimize later if needed
  2. Align Chunk Size with Embedding Model
    • text-embedding-3-large: 256-512 tokens
  3. Use Overlap (10-20%)
    • Prevents information loss at boundaries
  4. Add Rich Metadata
    • Source, date, author, category
  5. Test and Measure
    • A/B test different strategies
